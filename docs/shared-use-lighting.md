# 有来源的普通多用途共同照明

附加来源标签本身不能证明用途，缺少评估的兼用功能仍然阻断。本功能允许项目明确解释普通多用途空间，并以每个用途的源绑定标准类别计算共同约束，不把兼用标签删除或改成别名。

在 `room.secondaryUseAssessments` 中，每个 `secondary_use` 标签须恰好有一项评估，包含标签ID、声明用途、工作面、`standardSpace` 类别与依据、项目来源ID、解释状态和说明。功能来源至少包含一份任务书或审核指令；建筑名称、标准名称或标签相邻都不能单独建立实际功能。未知/临床用途、额外或重复评估、未声明标签、来源不明继续拒绝。医院示教室或电梯不能因本例存在会议类别就自动映射为会议用途。

当前唯一支持的方法是 `shared_layout_all_uses_same_conditions`：所有用途共用一套固定灯具布局、工作面、封闭表面及明确的观察条件，全部同时满足共同指标。要求声明源绑定标准、IES逐点模型、有限光源漫反射条件及参考UGR。不同工作面不换算，分时调光、不同姿态/工位、开口/设备或多个照明场景需要分别评估，尚未支持。

每个用途分别核对标准版本来源、类别允许用途、工作面及客户照度上限，保留原始分类理由、组件规则及源页证据。实际标准下限取所有用途照度、均匀度和Ra的最大值，上限取LPD和UGR最小值，再与未修改的项目要求取严格交集；没有自动功率修正或照度折算。综合记录仍保留主类别ID用于兼容，但 `aggregation`、`useClassIds` 与 `useAssessments` 明确表示计算的用途交集，不冒称标准新增的房间类别。

每产品点诊断池仍限16个；先覆盖不同灯数的代表几何，再保留有限变体。数量族超过预算时兼顾低数量、利用系数估计目标附近及全范围分层；估计只用于诊断采样，不是总照度预测或可行性判据。覆盖数量和未穷举范围进入决策记录，不能将预算内失败宣告全局无解。

缺少任一用途规则或存在冲突时不丢弃该用途。产品候选必须允许全部声明用途；候选用途限制及名义Ra仍是待独立核验的产品数据。仅有填写好的评估表不能通过：设计要求完整源绑定依据，独立检查器重新计算共同约束并核对所有组件；总照度和已请求UGR必须实际通过，才能发布共同布局和交付。数值稳定、参考眩光通过和专业适用性分别记账。

输入、组件规则和解释均保存在冻结模型中，项目原始约束不被改写。源规则配置变化阻断交付；既有修改需求与采纳机制继续使旧模型/审核失效。CAD设计说明列出每个共同用途及类别，审核报告列出各自指标、来源和共同约束。`status` 的 `space_uses` 分区核对模型摘要后返回用途依据；任务中心可查看全部用途与实际项目/标准交集，不能只显示较宽松的主用途指标。

本轮验证复用已知的程序构造8×6m建筑几何，由程序明确给出普通办公兼会议任务；不是未见项目、真实客户或AI理解新任务的验收。建筑来自独立构造源图，厂家IES和已核读标准子集按原摘要使用；标准/功能适用性、实际安装及产品23W/24W差异继续待审。共同站姿参考不代替坐姿或实际工位验收，也不外推医院全楼层能力。

医院既有兼用电梯解释没有获得功能、分类和独立建筑依据，本功能不会解除其阻断，也不生成替代医院设计。原医院主交付及隔离对照保持不变。缺少任务、工作面冲突、未知标准、产品用途受限和来源变化的负例，与真实MCP/Radiance/CAD验证分别记录。最新结果见[共同用途验证](shared-use-lighting-validation.json)。M2—M4仍未完成。
