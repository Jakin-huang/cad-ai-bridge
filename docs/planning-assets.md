# 声明物品参与空间求解

空间规划输入的可选 `assets` 将设备、储物柜、普通工作台等平面物品交给已有公共求解器。项目名称不参与路由。医院后勤、学校支持空间和办公测试使用同一专业包，测试名称不代表新增临床、教学或建筑专业认证。

每项清单声明 `id/roomId/name`、`widthMm/depthMm`、`orientations`、`clearances`、`minFrontAccessMm`、来源ID、状态和原句。最多32项、每个空间8项。宽深是物品本体在零度时的世界X/Y尺寸；零度正面朝世界南，90度朝东，180度朝北，270度朝西。四个净空分别为物品自身的前、后、左、右。`fixed:{position,orientationDegrees}` 的position是旋转后本体包围框的世界最小XY，不是中心点；固定坐标不吸附网格。

尺寸与净空须由输入声明，不从名称推产品参数或规范数值。每项须有有效需求来源和字面引文；固定位置另须建筑来源身份。来源身份和引文字面通过，不代表现场或条文已核验。`unresolved` 清单会阻断设计，`assumed` 继续保留假设等级。

`conditions_only` 可以先冻结物理清单、保持程序为空；Agent随后从原文解释完整房间程序，最终每个roomId必须存在。当前intake把物品作为冻结物理条件，不开放在逻辑草稿中改值。`revise_program` 保留清单和来源等级、重绑当前需求来源，新brief须继续包含原物品引文；删除所属空间或改动清单不能静默通过。当前接口没有物品清单换版或固定设备移动的承诺。

## 实际求解与检查

求解器在候选房间内安排物品，固定物品优先，其他物品按允许朝向及项目网格尝试与房间、障碍边缘有关的有限位置。物品搜索与房间搜索共用节点和时间预算。它是有界搜索，失败不能证明实际工程无解；当前桌椅仍使用已有布局族，不枚举所有家具布置。

检查包括清单无遗漏/重复、所属房间、本体尺寸与朝向、固定坐标、前后左右操作区域、座位与桌椅、门口、房间间直接门及通道冲突。操作区域彼此不重叠，本体不占用已检查的通道。正面操作区域须按声明宽度接触门连通通道；`minFrontAccessMm=0`明确表示本次不要求这项接口检查，不能称作已验证操作可达。

独立校核从原声明重新推导朝向和净空，不采信求解器给出的尺寸或固定状态。分隔平面和家具平面均有物品本体、对应编号及绑定输入摘要的隐藏属性；家具平面另有净空框。SP06及assets CSV列出尺寸、位置、朝向、固定状态、净空、假设等级与来源。原生CAD保存重开检查实际几何及属性；共享空间的context保留本体平面轮廓，但不把它自动解释成有高度的光学遮挡或完整机电模型。

图面物品不能盖住房间标签。渲染第7版在物品/操作区和门口之外搜索房间文字位置，找不到位置即阻断；不为容纳文字移动设备。第6版失败图保留其原始渲染和状态，不追认为新标注规则通过。无物品的旧输入继续使用原图面逻辑。

## 验收边界

这项能力验证的是明确声明条件下的平面子集：不认证设备性能、荷载、电气给排水接口、临床感染控制、完整维护路径、消防、无障碍或施工可用性。这些保留为待审条件。原始委托没有物品清单和实测条件时，不能用开发测试尺寸代替真实输入。

本机回归、真实Agent/CAD、逐页图面结果和保留失败见[验证记录](planning-assets-validation.json)。复杂项目最终目标及独立客户/专业审核仍单列。
