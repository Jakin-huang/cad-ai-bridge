# 真实客户端修订验证与实际边界

本轮用独立合成办公数据检验通用流程，医院仍是独立示例。客户端从新任务书判断空间范围、用途、变更值和缺项；Bridge 装配并检查来源、几何和版本，继续执行设计、自检和原生出图。没有新增医院文件处理或外发，冻结 v2 用户包和 DLL 未改。

## 实际结果

| 用例 | 最终保存结果 | 执行中的实际问题 |
|---|---|---|
| 正常修订 | 删除 TEAM、新增 STUDIO，OFFICE_A 改教学用途，目标分别为450/550 lx；五空间新设计完成 | 首次提案漏改目标，客户端读回后自行修正，正式应用前纠正 |
| 矛盾要求 | STUDIO 的550和650 lx均保留，新输入blocked，无新模型或出图 | 两次提案尝试，最终不擅自协调冲突 |
| 未知用途 | 新增 ARCHIVE 仍为unknown，未编造照度和控制，新输入blocked | 首次引文不符被Bridge拒绝；客户端自行修正。最终状态通过，零错误可用性未通过 |

三个最终状态共244项核验、33项独立原始请求/落盘证明核验。原完整接口首轮约24分钟内反复违反参数/来源链要求，被受控停止，原版本和旧模型保留；失败轨迹没有修成成功。新的紧凑接口源码实际Schema约7 KB，旧完整接口约121 KB；这不是受控性能对比。

正向新设计为52灯、5回路、1248 W，101项模型子集检查和5项保存后原生捕获检查通过，36个新旧成果摘要核对。新建1份DWG、五页PDF待审图册；五页均核对物理尺寸并直接查看渲染，图面显示范围、假设、450/550 lx目标及待审事项。原AutoCAD PDF解析出现重复PageMode字典警告，仍可重开和逐页渲染，原文件保留。图面可读性不等于工程质量或专业签审。

最终全量单元回归372项通过。另在新的只读MCP进程中来回读取五个既有照明/空间设计任务，6次调用、67项摘要检查通过；这是已有任务兼容检查，不能抵扣未见任务质量验收。

## 实现与核验边界

- `inspect_brief`限定输入根内UTF-8文本，返回原文、rawSHA256和textSHA256；`space_bindings`直接返回原功能对象摘要，原共享包不改。
- `cad_design_revision`接受客户端明确的空间、用途、旧条件来源、变更/未知规则和逐字原文。Bridge只装配技术记录，不选择照度、标准或未知用途。先读不可变提案，再经既有完整来源/版本/假设门槛应用；旧模型、质量、图纸和审核失效，历史字节保留。
- 可选反射、眩光、产品、供电和待审条件不能在换任务时丢弃或放宽。多功能附名及未表示的权威依据变动继续使用完整接口，不自动猜身份和专业适用性。
- 本轮补充审计发现原测试器漏算了外层成功、内层Bridge `ok=false`的拒绝。原始报告未改，新增独立深层审计纠正其零错误结论；后续测试器已修正，并有区分正常blocked与工具失败的回归。

这是每类一次的已知合成试验。客户端得到公开技能、流程提示和旧任务条件，核验表在调用前冻结且不在客户端读取范围内；没有控制器修补其工程解释。只证明这三个最终状态和正向原生流程，不证明首次提案可靠、任意自然语言理解或独立客户验收。WorkBuddy使用当前默认auto配置，实际路由模型/提供商未确定，不宣称固定模型基准成绩。

## 下一优先级及退出条件

1. **P0：需求覆盖与可靠审阅。** 扩展独立表述、遗漏、多文档冲突、引文错误和跨任务保留。分别记录首次提案、修正次数、工具拒绝、最终正确率；不得只检查最终数值或把引用摘要当语义正确。
2. **P0：原整层光学失败。** 按原500 lx等条件重新验证，保存全范围物理证据和预算结果。原478.253 lx失败保留，不能用本轮流明估算通过替代。
3. **P1：空间布局及专业依据。** 扩大源绑定布局族、明确拆并/兼用身份、多文档来源变更和标准适用性。照明、空间方案、分析分别回归，不能依项目名切换专业或套医院答案。
4. **P2：独立实用验收。** 独立真实任务书与工程图、新机器、外部用户和认证专业审核分项完成。当前普通照明5/11空间、有界直走廊矩形办公布局和全部假设数值，不能代表完整项目完成。

M2—M4、独立实用验收和完整发行闸门仍未完成。详细计数、原始失败与工具拒绝口径见[机器可读证据](scope-client-validation.json)；实现和验收总计划见[完整方案](engineering-design-plan.md)。本机证据包另含冻结输入/核验表、全部轨迹与未采纳提案、原生成果、图面检查和逐文件SHA清单，不进入公开源码或发行包。
