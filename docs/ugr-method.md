# 参考房间 UGR：输入、范围与验收

本功能是冻结普通照明布局后的可选复核，不是医院全场景眩光评价。计算器不读取医院最终对照灯位，也不将厂家标称 UGR 当作房间结果。布局搜索目前仍使用维持直射逐点照度；总照度和 UGR 是独立出口门禁，尚未驱动自动重选布局。

## 来源和解释

算式、适用发光面积、观察位置、参考表面与位置指数表依据本机核对的 [GB/T 50034-2024 原件](https://zcsys.ncepu.edu.cn/docs/2025-01/d5c197c2837e4892ac7d02faae298500.pdf) PDF 第80、82、83、84页。原件、页像素摘要、交叉核对文件、完整位置指数表和解释配置只保存在操作者本地资料区。公开仓库不附带标准全文或表格。

导入命令 `python scripts/import-ugr-evidence.py MANIFEST EXPECTED_SHA NEW_PROFILE` 拒绝覆盖旧配置，核对原件、页像素、交叉文件和表格结构。导入成功证明身份和完整性，不能自动认证数值转录或专业适用性。默认配置为本机资料目录的 `engineering-ugr-rules.json`，操作者可用 `CADBRIDGE_ENGINEERING_UGR_RULES` 指定另一受控版本；客户端不能提交可执行程序。

`ugr_basis` 只返回方法标识、摘要、来源页和范围，不返回完整位置表或私有路径。输入 `glareAssessment` 必须绑定该标识与摘要，并同时声明 `lightingStandards`、房间标准类别和 `lightingEnvironment`。每个房间明确姿态、UGR上限、参考工作面/墙面/安装面反射率、来源及假设状态。

位置比值在表格节点时使用原值；节点之间采用有效包围单元中最小的位置指数，对应较大的眩光项。这是明确登记的本地保守解释，尚需专业确认；不能声称标准规定如此插值。遇到原表空白或超出边界时阻断，不外推、不假定忽略该灯、不用另一经验公式填补。

## 声明模型

- 只支持矩形无内部障碍房间、相同安装高度、与房间轴线对齐的矩形向下发光面；面积严格在0.005和1.5平方米之间。双对称性按原始角度节点及镜像节点检查，容许差为峰值光强的1%，仅是数值模型条件，不是标准规定或厂家认证。
- 四个墙面中点、水平向内视线。坐姿眼高1.2m、站姿1.5m，由明确输入决定；一种姿态的结果不替代另一种。
- 参考下表面在0.75m，上表面为灯具安装平面，安装面按发光开口真实开孔。它与实际地面0m、物理吊顶的总照度场景分开计算。
- UGR采用初始光输出，维护系数1；平均维持照度仍按项目维护系数计算。背景亮度由间接眼部照度除以π得到，不能把总眼部照度代入。
- 发光面按IES尺寸及远场配光构造均匀近似。非均匀亮度、近场、实际开口/家具/工位视线、日光和现场产品证据未验收。

Radiance计算参考场景的直射及两档总眼部照度，两档UGR均不能超过任务/标准上限的较小者；观察到的两档变化须不超过0.25。这是软件稳定性条件，不是标准误差上界。原始IES、场景、传感器、命令、光照输出和观察位置CSV均保留并绑定摘要。

## 产品出口

请求UGR后，`assess_lighting` 将其与总照度合并检查。缺失、超限、范围不支持、来源变化或原始证据修改都不能进入新CAD交付。`status` 与历史报告保留原结论，`deliver` 重读当前方法来源和摘要并重新计算门禁，不信任保存的 passed 标记。需求修改会使旧复核失效。

图册保留直射选型计算口径，反射总照度和UGR另附报告与CSV，不能混成一个数值。结果始终 `professionalApproval:false`；真实客户、新机器、独立项目和专业审核另行验收。

自动检查分开记录：单元正反例；真实MCP/Radiance/CAD门禁；独立Python公式及有限光源直射眼部照度面积积分；同引擎中/精档稳定性。后两项互不替代。公式和积分核对也不证明间接光模型、产品亮度真实性或工程适用性。
