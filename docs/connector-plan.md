# CAD AI Bridge 现有项目完善与优化方案

更新日期：2026-10-16。

本项目继续作为用户现有 CAD 软件与 AI 之间的中间层，通过 MCP、Skill 和 CLI 开放已验证的软件操作能力。近期开发以现有实现为基础，优先降低接入成本、提高稳定性、缩短等待时间。每项改进需要解决明确的使用问题，并保留现有能力和验证证据。

本文替代此前以通用命令框架和常驻会话为主线的实施安排。能力范围以[技术方案](technical-plan.md)和[工具契约](tools.md)为准；下列六项清单规定本轮实施与验收范围，具体结果见交付记录。

本轮已按下列六项清单完成实现，并开展原有宿主、工程和学校回归。具体实现、测量及验收范围见[三批优化交付记录](maintenance-validation.md)；后续候选仍按实际收益决定。

## 方向与范围

用户继续使用已有的 AutoCAD、天正、图纸和 AI 客户端。MCP 承载工具调用，Skill 说明如何完成任务，中间层处理环境、文件、宿主执行和结果核验。用户不需要管理请求 ID、文件摘要、内部路径或进程。

现阶段继续围绕 Windows、AutoCAD 2022、天正电气 V8.0 的已验证环境完善。学校生成器保留为复杂业务回归样本，WorkBuddy 等客户端用于检验接入体验。新增通用能力由实际任务推动，不以命令数量和架构规模评价进展。

客户端接入沿用同一 MCP 服务和 Skill 内容。客户端差异限于必要的启动配置、Skill 安装说明、图像和文件展示；不为每个客户端维护一套绘图逻辑。MCP 协议兼容不自动保证所有客户端的展示、超时和配置行为一致。

## 必须保留的基础

| 已有能力 | 优化中的保护要求 |
| --- | --- |
| MCP、CLI、既有工具名称与数据契约 | 优先保持兼容；结果字段采用兼容扩展，需要破坏性变更时单独说明迁移 |
| AutoCAD CoreConsole 与天正图形宿主 | 按现有能力选用，保留两条已验证的执行路径 |
| 设备与导线读取、统计、布置、连线、编号 | 保持已声明范围，不因内部整理减少可用操作 |
| 原始审计、工程副本、修复副本与场景创建 | 保留源图快照、独立输出和任务证据 |
| 文件摘要、文档身份、版本检查、事务回滚和请求幂等 | 优化耗时和结果返回时不得绕过或降低这些检查 |
| 结果摘要、分页、只读模式 | 保持返回预算与只读限制；读取已有证据无需重启 CAD |
| 学校样本、本地标准库及独立回读 | 保留现有流程与验收，作为复杂操作链的回归资产 |
| 配置备份、宿主进程归属、安全加载及配置恢复 | 不影响用户其他进程、配置、图纸和软件授权 |

现有写入继续在快照上执行并输出新文件。直接编辑用户当前文档属于后续专项能力，近期维护不改变原图保护和保存语义。项目不要求用户迁移 AI 平台或额外配置模型 API 密钥；返回给 AI 客户端的数据仍受该客户端的数据处理方式影响。

## 近期实施清单

近期清单限定为六项，按 A1、A2、B1、B2、C1、C2 推进。每项独立交付、独立验收，只有出现具体问题才扩大改动范围。涉及同一模块的整理随功能完成，不先做整体重构。

| 编号 | 问题与改进 | 最小交付 | 验收依据 |
| --- | --- | --- | --- |
| A1 接入失败可诊断 | 模块导入即检测 CAD，环境缺失容易表现为 MCP 连接失败 | 将实际宿主初始化延后；提供不依赖 CAD 可用性的诊断入口；明确配置、工作区、插件和版本问题 | 缺少 CAD、PowerShell、插件或有效配置时，MCP 仍完成握手并给出相应诊断；已有工具保持可发现且不可用原因明确 |
| A2 简化安装与连接 | 当前开发者配置与构建步骤增加用户成本 | 完善现有 setup、doctor、便携包和通用 MCP 配置；自动准备路径；复用一份 Skill 与简短接入说明 | 普通用户按说明可完成接入；不手填 JSON 和环境变量；已有配置先备份且仅修改本项目条目；中文与空格路径有效 |
| B1 错误与输出状态清晰 | 宿主、输入、导出及保存问题容易混成一类错误 | 沿用现有错误结构，补充明确的失败阶段、可读解释、输出状态及证据定位；已有代码保留可兼容识别方式 | 输入失败、启动失败、超时、事务失败、DWG 保存和 DXF 导出失败可区分；已保存的文件不会因后续导出失败被当成未执行而重做 |
| B2 可靠重试与故障恢复 | 写入超时或客户端断连后，重复调用可能造成状态误判 | 完善已有任务记录与查询，复用 UUID 和结果证据；界定何时可重试、何时须核验；补齐自有宿主退出与配置恢复 | 重复请求不重复修改；状态不明时不自动重放；恢复查询可定位已有结果；失败不影响原图和其他 CAD 进程 |
| C1 测量并优化现有调用 | 目前总耗时缺少分段依据，重复检测和不必要的重新执行增加等待 | 记录环境检测、快照、排队、宿主启动、执行、保存、导出与结果处理耗时；消除已证实的重复工作 | 同一环境与样本对比优化前后时间、启动次数和返回量；摘要、分页继续复用已有结果；节省不能来自省略保护与验收 |
| C2 改善批量调用与结果读取 | 多次小操作、冗长结果和重复完整读取增加软件与 AI 调用成本 | 完善现有 electrical_apply 的批量使用指引、默认摘要、分页和同一任务结果复用；让 AI 自动传递内部参数 | 完成同一任务的宿主启动次数、工具轮次和返回字节数可对比；回滚、编号冲突、幂等与保存重开结果保持一致 |

A2 首先改进已有分发流程。普通用户包应携带经过匹配宿主验证的本项目插件，并自动检测或准备必要运行依赖；开发者保留本地构建入口。版本或插件不匹配时清楚说明，不能让用户自己猜 SDK、DLL 或 PATH。运行时分发及离线包按实际发布需要逐步完成，不以构建完整安装平台为前提。

B2 优先利用现有任务文件和请求记录，不先建设完整异步任务平台。若已有证据无法区分“未执行”与“已执行但未返回”，应保留状态待核实，并说明恢复办法。数据库提交、保存和记录落盘存在不同边界，不能承诺任意崩溃窗口都能自动恢复未保存状态。

C1 允许对重复环境检测做受控缓存，但要明确有效期与失效条件；配置、插件或宿主路径变化需重新核验。缓存不替代输入文件摘要和实际宿主检查。是否改变现有 DWG/DXF 输出时机，须先核对调用者和验收依赖，保留当前默认交付契约。

## 操作体验要求

默认流程是“安装或解压 → 自动检测并生成连接配置 → 在现有客户端启用 → 用自然语言完成任务”。软件自身授权和客户端必要权限按原有流程完成；只在安装选择、工作范围或任务目标存在实际歧义时询问用户。

MCP stdout 只承载协议，日志进入 stderr 或任务文件。错误首先说明发生了什么、原图是否受到影响、已有结果如何获取以及下一步如何处理；技术细节按需展开。诊断和读取既有结果不应因为 CAD 当前不可用而一并失效。

Skill 优先说明现有工具的正确组合、批量操作、读取摘要、必要时分页及结果核验，不要求用户学习中间层内部协议。通用能力描述来自真实可用范围，不能提示 AI 调用尚未实现的工具。

配置位置可确定时生成或合并配置；位置无法确定时提供可直接导入的文件和最短说明，不猜测客户端私有目录。升级保持稳定启动入口、配置备份和已有图纸可访问性。未验证的客户端只声明协议适配预期，不能声明实际接入通过。

## 后续按收益决定的增强

以下内容保留为候选，不再是近期实施前提，也不与六项维护清单捆绑发布。

| 候选 | 启动条件 | 首次验证范围 |
| --- | --- | --- |
| 实际图纸局部预览 | 结构化结果仍无法有效判断位置、遮挡或图形效果 | 在现有一次性宿主任务中生成局部图像，关联输入摘要与结果文件；图片失败不重放写入 |
| 专用常驻会话 | 同一实例重复任务的测量证明启动成本是主要瓶颈，现有批量优化不足 | 保留批处理后端，验证单文档、少量已有操作及断连行为；收益与维护成本实测后再扩展 |
| 用户现有 CAD 会话 | 真实任务需要操作已打开文档，副本批处理明显增加操作步骤 | 先验证目标文档、人工编辑冲突、文档锁和保存意图，不误关用户进程 |
| 通用命令与更多原生能力 | 多个实际任务被同一缺失操作阻断 | 只补齐必要查询或修改，复用现有契约和处理逻辑；原生命令单独验证完成、取消和撤销行为 |
| 命令注册表及模块拆分 | 重复实现或维护问题已经明确，局部抽取可减少错误 | 随对应优化小步引入，保持旧工具接口与现有回归 |
| 多客户端协调与其他传输 | 出现实际同时操作或远程接入需求 | 在需求范围内处理冲突和认证，避免增加普通本地用户的配置步骤 |

CADCraft 继续作为命令组织、会话和反馈方式的参考。是否采用某种机制由现有项目的问题和测量结果决定；本项目使用已有 CAD 软件及插件能力。

## 验收与发布

验收分为既有能力保护和新增收益核验。每项优化同时回答“解决什么问题、减少哪些步骤或等待、哪些原有能力经过复核”。

| 类别 | 通过条件 |
| --- | --- |
| 接入成本 | 记录从获得安装包到工具可用的总时间、下载时间、用户操作时间、手工步骤与失败恢复步骤；默认无需手改配置和手工编译 |
| 启动诊断 | 正常环境与缺失依赖环境均能完成 MCP 握手；诊断能指导用户解决对应问题 |
| 真实客户端 | 至少在 WorkBuddy 和另一个独立 MCP 客户端验证当前支持的读取、写入、结果获取及只读模式；Skill 安装差异单独记录 |
| 稳定性 | 保留身份、摘要、版本、回滚、幂等与源文件保护；补测本次改动影响的超时、断连、保存及导出失败路径 |
| 效率 | 使用相同机器、图纸与操作比较分段耗时、宿主启动次数、调用轮次和返回字节；冷／热状态及样本规模随结果记录 |
| 安装维护 | 普通用户权限、中文与空格路径、已有配置、缺失依赖和更新后重连在对应发布范围内通过 |
| 输出正确性 | 独立 CAD 重开与 DXF 对照继续有效，图片和样本业务计算不代替实际图纸结果 |

可先以本地 MCP 启动和工具发现 5 秒内作为试测目标，前提是先收集当前基线；初次安装耗时必须包含必要准备并分别记录下载。暂不承诺新的热调用指标、2 秒异步提交或常驻连续操作次数，避免把尚未决定实施的架构写成发布门槛。

文档与配置说明修改运行链接、公开文件与静态发布检查。运行时代码修改增加针对相应故障的测试，并运行现有离线回归。涉及 CAD 插件、宿主启动、持久化或天正行为时，运行普通 CAD、天正及受影响的工程／学校回归，核对当前 DLL、源文件摘要和真实宿主证据。已有报告不能冒充新版本实测。

按小批次交付：第一批完成 A1/A2，第二批完成 B1/B2，第三批完成 C1/C2。每批可单独发布维护版本，不等待后续架构候选完成。运行时与插件版本按实际兼容变更管理；本方案本身不修改当前版本号。

## 2026-10-19 能力扩展阶段

在维护与接入优化之后，新增已有图纸查询、批量编辑和真实CAD出图。保留原有15个工具，新工具为cad_query_entities、cad_edit、cad_export，沿用同一MCP、Skill和中文接入入口，不增加用户配置步骤。完整范围见[编辑与出图](editing.md)和[preview.4说明](releases/v0.2.0-preview.4.md)。

新增操作按真实CoreConsole与天正宿主分别验证，覆盖保存重开、独立DXF、实际PDF/PNG、事务回滚、旧UUID重放和原图摘要。天正原生桥架、厂家专有标注和未验证原生命令尚未完成；普通路线文字标签不作为这些原生能力的替代。未完成项不列入已交付能力。
