# v2.1.0-preview.1：通用工程 Agent 迭代

本轮按四步方案交付一个有限、可复核的版本增量，并推送源码。产品目标仍是将工程需求转化为可编辑、协调、可审核的设计。医院、教学、办公是验证场景；不作为公共流程的路由条件。原 v2.0 标签和发行包保留。

## 范围与退出标准

1. 统一入口：复用已有持久化工程任务、原文、输入草稿、操作收据和专业包，增加只读 next_step。返回当前阻断项、下一操作及当前版本参数；不另建一套项目数据库。未知操作结果、过期来源、检查失败不能被引导继续出图。
2. Agent 闭环：更新公开 Skill，贯通原文审阅、条件准备、设计、检查反馈、修订、交付、待人工审核。模型负责解释和选择，程序提供状态和可执行接口。一次只推进一个已确认操作；失败后读取新状态，禁止改 UUID 重做未确认写入。完成执行指引不等于自主理解已验收。
3. 公共求解：完成已在开发的房间开间差约束。由原文显式提交关系，求解、独立检查、图纸一致执行；不按案例名称分支。检验不同朝向、面积偏好、容差和冲突，同时回归照明与原空间能力。本轮不新增其他大型专业包或无关优化。
4. 交付与复用：在医院、教学、办公场景中运行同一状态引导协议，使用有实质差别的用途、几何、设计要求或缺项；分别记录设计/检查/原生出图/语义理解/独立项目/专业审核。开发合成数据、历史只读复核不能冒称新客户完整项目。全量回归及源码隔离检查通过后提交、标记版本并推送；实用验收未通过的范围在版本说明中列明。

## 本轮优先级与收敛规则

P0：收尾已有真实 CAD 修订验证；实现并验证跨专业 next_step；完善通用 Agent 指引。P1：完成三场景协议与回归检查、版本记录和推送。上述退出标准完成后结束本轮迭代，剩余更复杂布局、更多专业、跨模型评测、外部用户/新机器及专业签审进入后续版本，不在本轮滚动扩项。

每项新增能力说明解决的公共问题、适用条件、案例证据和剩余限制。场景专属规则进入输入/专业配置；公共模块不含医院/学校名称判断。不能用测试数量、页数、覆盖处置率或数据隔离单独证明复杂项目设计完成。

## 本轮结果

开发实现及已声明范围的本机执行验证完成。547 项最终全量回归通过，Skill 官方校验通过。三类不同开发问题共用 next_step，生成3份 DWG/15张审核PDF；另外接续完成等开间修订1份 DWG/5张审核PDF，原23份登记成果保持。25张含旧基线的审核PDF严格解析、纸张核对和逐张目视完成。学校首轮标注失败保留，公共修复后原模型不变并完成交付；不将恢复后成功写成首轮零错误。

实用性验收仍未完成：本轮由实际 MCP 驱动器按 next_step 执行。另启动一次已登录模型客户端的三场景只读接续试验，模型服务返回额度耗尽，未取得接续通过；进程退出码为0也不作为成功。没有新增模型从陌生原文到CAD的自主试验，也没有独立客户项目、跨模型、新机器、外部用户或专业签审通过。源码版本与标签发布，不重打或替换原v2.0用户包；旧完整打包门槛的DLL证据差异不予放宽。详见[验证范围与剩余差距](v2.1-validation.json)。

下一版本优先完成原始委托到结构化任务的实际Agent解释与修正评测；保留本轮医院/教学/办公的不同问题回归。进一步布局/专业能力须由实际失败推动，不能新增案例特判或扩大本轮发布范围。
