# 新来源下保留物理基线重新准备

2026-10-24，本轮补上带scope的需求准备任务在原文换版后的入口。旧形式任务的manifest及scope保持不可变；新来源不能解除旧任务的失效校核。满足条件时，Agent可以重用原来单独冻结的物理基线，依据新原文重新解释需求，生成显式关联前版的新任务，并完成新的设计与审核输出。

入口为 `engineering_intake capabilities section=repreparation` 及 `action=reprepare`。入参包括原task身份、expectedInputSHA256、新documents、新scope、reason和变更来源的原句。必须是intake创建且带scope的任务，输入仍为初次采纳的修订0、没有未确认操作；新旧项目、专业和workItemId保持，新documents是同一原文集合的较新当前版本。至少一份实际变化的需求、协调或建筑说明文件须提供字面证据。未知范围、失效前置、错误身份和输入修订均拒绝。

工具复制的是原独立物理baseline.bin及baseline.json，不复制旧模型或把旧设计当新需求答案，也不接受新物理值。原项目和专业元数据保持；新的baseline带reprepares、前版输入及草稿身份，默认强制重新声明原文支持的title/scope/notes和完整空间清单。后续仍须重新draft、逐段sourceCoverage、读回核对、commit、设计、自检、CAD和review_pdfs；本入口不自动解释自然语言、延续条件、变更标准或批准工程。

新正式任务的preparationLineage及可下载JSON关联前版、原物理基线和新草稿。任务每次加载校核不可变记录、物理快照和关联文件摘要；待审项目报告可保留并展示前版关系。原任务、源文、图纸和审核包保留历史。原任务已有输入修订或来源驱动的物理改动时，本入口明确拒绝，不能通过回退到原初基线丢弃后来变更；这部分仍需对应修订流程，不宣称已支持同一task ID内部迁移scope。

两类设计包的回归验证物理基线逐字节相同，照明供电和空间壳条件保持，新逻辑需求与前版关联正确；读只模式不能重新准备，前版未确认或修订后新采纳被阻断，篡改草稿、物理快照或关联JSON会被拒绝。最终611项全量通过，0失败、0跳过。
