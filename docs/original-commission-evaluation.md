# 原始委托完整性评估

这项评估回答“Agent是否保留陌生委托中的实际义务和限制”。它不以生成图纸数量或源段覆盖率替代设计能力验收。

本轮使用独立作者发布的[UNDP办公改造原始委托 IC/PNG/055-2021](https://procurement-notices.undp.org/view_file.cfm?doc_id=273349)。这是2021年的历史委托，不能用作现行法规或规范。完整PDF及七页规范化原文仅存本地资料区；公开源码只保留来源地址、SHA256和运行器。页面均已渲染检查，未含建筑底图或最终布局，不存在从成图反推设计输入的步骤。

## 如何判定

在首个真实客户端启动前，冻结38条工程、协调及交付核对标准，并保留原文位置和引文。模型工作目录和工具文档集中均不包含此清单、预期答案、种子方案或最终图。模型通过实际MCP读取七页原文、查询现有能力，自行提交范围解释及源段处置，再分页读回核对。

核对分两部分：运行器独立重算来源哈希、实际读取范围、引文、不可变审阅和源段覆盖；本地评审者再逐项比较工程含义、条件、前置批准和交付形式。引文重叠只作为待检查线索，不自动判为语义满足。分母不随结果更改，未支持的工程义务不能改为背景，未解决的源段继续阻断准备。

来源作者独立于本项目；清单制定与语义判读由本地开发评审完成，没有外部专业评审者。重跑同一资料属于已知用例回归，不能计作第二份陌生委托或独立客户项目。38条标准也不替代完整法律、商务和招标审查。

## 工具改进

`cad_engineering_intake capabilities section=scope` 现在返回完整的 `reviewActionSchema/readActionSchema`，保留原兼容字段，并明确范围审阅采用顶层字段，不套用其他动作的 `parameters` 形状。未决/冲突工作项不满足受支持映射的规则，对应源段须保留未解；不能靠改成背景消除阻断。通用Agent参考同步说明这些区别，适用于不同项目类型。

真实重跑还暴露了语言相关的接口障碍：完整的中文工作描述因不足10字符被拒。描述改为非空正文、保留2000字符上限；不是放宽设计要求或语义验收。原文证据、理由、未解项、能力与依赖检查继续执行，空白描述仍被拒。最终真实客户端先于这项字符规则修正；随后以保留的失败调用和本机测试验证兼容性，不把它宣称为又一次客户端或CAD验证。

复现需要已安装、已登录的实际客户端，以及经固定哈希核验的公开来源快照。不会读取登录凭据或覆盖模型配置：

```text
node tests/codex-public-scope-client.mjs <installed-cli> <public-source-folder> <new-evidence-folder>
node scripts/audit-public-scope-client.mjs <evidence-folder>
node --test tests/unit/scope-intake.test.mjs
```

脚本只允许本轮固定公开资料，不接受任意私有项目替换。原文提取为UTF-8 LF，各页哈希见 `tests/helpers/public-office-commission.mjs`；取得原件后用PDF工具提取、规范化并逐页核对，不能把网页摘要冒充完整PDF。语义判读仍须另行执行，脚本的 `ok` 仅说明所列协议事实通过。

## 下一步与退出条件

结果与保留失败见[验证记录](original-commission-validation.json)。本轮不新增工程专业，不生成虚构建筑条件，也不重新打包冻结发行版。

下一项实用开发应优先把已登记的既有设施、设备及家具要求交给公共设计求解：来源支持的尺寸/位置、保留条件和操作净空必须参与布局及独立检查，而不是只出现在说明里。缺少实测条件的原项目继续保持未完成。开发验证可使用明确声明的不同项目测试条件，但不能将这些条件升级为真实现场资料。

这一后续能力的退出标准应包含：需求到实际约束的对应、保留对象不被移动或遗漏、无解冲突可追溯、图面及设备表一致、不同项目复用及真实CAD保存重开。单一公开委托解释通过仍不足以退出复杂项目设计阶段；独立建筑输入、真实产品与标准适用性、跨专业协调和专业审核继续单列。
