# 求解前的必要条件诊断

复杂任务需要区分“输入已解释完整”“声明约束能否同时成立”“当前搜索找到方案”和“工程可交付”。本增量在普通照明、空间规划两个设计包共用诊断结构，将计算依据接入真实求解入口及 `cad_engineering_task action=next_step`，不按医院、学校或办公名称选择规则。

`next_step.feasibility` 绑定当前 `inputSHA256`，包含 `reportSHA256`、检查适用模型、原值/单位、乐观上界、差额、公式和带来源/等级/数值摘要的操作数。该读取不修改任务、旧图或来源。历史任务同样按当前代码只读计算，原试轮结论保持原样。

| 结果 | 含义与后续 |
| --- | --- |
| `declared_model_conflict` | 至少一个必要条件不成立；保留输入，在获得有依据的需求、物理或产品变更前停止该任务。 |
| `no_necessary_conflict_found` | 仅未发现这些必要条件冲突；继续求解、自检、真实 CAD 和审核 PDF 流程。不能当作可行性证明。 |
| `not_evaluated` | 模型不适用、输入尚未明确或数值无法可靠计算；保持未知并使用适用的输入/专业检查。 |
| `budget_exhausted` / `bounded_family_exhausted` | 原求解器相应预算/布局族内没有候选；与必要条件冲突分别报告，均不证明工程全局无解。 |

## 已实现的边界

普通流明法：`E_est ≤ max_LPD × max(Φ × UF × MF / W)`。允许全部声明产品和连续混合功率分配作为乐观上界，忽略整数灯数、用途限制、标准等级、几何和间距的进一步限制。因此超过该上界能证明**这个声明估算模型**不成立；没有超过不能证明有可行布灯。必要功率密度/维持光效阈值只作为边界信息，不能自动写成新要求，也不保证采用后能出图。IES直射、反射和眩光模式不使用这个流明法诊断；标准适用性及真实光学性能仍需原流程验证。

空间规划：检查互不重叠房间的最小面积总和不超过整壳矩形面积，以及最小源窗接触长度总和不超过四侧不重叠源窗总长。面积上界不扣墙、走廊、保留构件和家具；窗长上界允许全部外立面，即使当前走廊布局族不能使用某一侧。这些是保守的必要条件，不提供完整面积分配、采光或专业规范合规结论。壳或房间程序尚未解决时不以占位数值判定冲突。

需求草稿仍可完整解释并采纳成任务，之后被求解诊断阻断。“草稿已解释完整”与“可产生方案”不会合并成一个通过标志。直接设计入口也执行诊断，不能跳过 `next_step` 绕过阻断；原质量、来源与交付闸门继续有效。

## 实际验证及退出范围

真实安装客户端使用三个已知结构化合成任务，控制脚本只准备输入，未提供诊断答案或执行 CAD。15 次调用、零客户端/Bridge 错误；19 项独立核对通过：

- 600 lx 流明法任务：8 W/m²、24 W/3600 lm、UF 0.6/MF 0.8，乐观上界576 lx，差24 lx；Agent 保留全部原值，未调用设计或出图。
- 空间任务：最小房间面积712 m²，整壳432 m²，差280 m²；窗长6400/12000 mm无这类冲突仍不能解除面积冲突。Agent 未改程序或出图。
- 独立500 lx任务：Agent继续设计并完成真实CAD保存重开、14盏灯/2回路/5页审核PDF；声明平均估算504 lx、7 W/m²。33项设计检查通过，5项仍待审。5页严格解析、纸张尺寸、原版与审核版像素一致性及逐页可读性核对通过。该任务是普通流明法，未做真实光学或安装设计验收。

原600 lx失败试轮、原500 lx重连试轮均完整保留。新增只读MCP检查确认二者现在分别返回声明模型冲突/无此必要冲突，451个原数据文件未改变；旧试轮整轮不通过的结论不会被新诊断或新试轮覆盖。历史只读辅助脚本最后复制自身时曾路径错误，检查报告已完成；原记录和补存动作分别保留。

单元回归包括连续混合灯具与整数枚举的上界比较、边界公差/极限数值、缺失冲突输入、不适用光学模式、面积/窗长独立冲突、未知条件、无必要冲突但布局族搜索失败、重启只读一致性和两包原生工作阻断。首轮全量有一项旧测试仍要求搜索抛异常，与新增更早的结构化阻断不一致；保留失败日志，更新为核对结构化原因、无设计产物和输入原样保留，再跑全量。最终数量和证据摘要见[验收记录](design-feasibility-validation.json)。

开发及上述本机合成使用闭环可分别验收。独立原始委托理解、医院整项目、多专业协调、跨模型、外部用户、新机器及认证专业审核仍未验收；M2—M4及总体目标未完成。本增量不重打发行包，不修改冻结v2.0或插件DLL。下一步优先扩大有来源的实质设计条件/布局覆盖，在独立多文档委托上检验需求完整性与工程完成度，避免重复已知案例代替目标。
