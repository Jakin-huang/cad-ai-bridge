## 本机效率结果

同机 Node 22.20.0、AutoCAD 2022、现有样本的单次对照：优化前重复环境检测为1496、1340、1352毫秒；优化后为1393、1、1毫秒。缓存仅适用于同一进程，过期或检测条件改变后重新发现。MCP 启动与工具发现由1973毫秒降为350毫秒；图纸处理不因握手而提前启动。

两设备、一条3000毫米路线与编号的合成任务，原子批量调用耗时3430毫秒、启动1次宿主；分拆成三个修改调用耗时10321毫秒、启动3次宿主。两条流程均保存后独立重开，设备、路线、编号一致，原图未变。批量能力原已存在，本轮改进其使用指引与测量，不把这种调用方式对照当成旧版本与新版本的几何执行速度比较。

上述数字是本机样本测量，不是跨机器保证、长时间统计或整体设计效率倍率。每项调用还分别记录配置、排队、快照、宿主、输出及插件事务／保存／导出耗时。

## 兼容性与回归范围

离线回归48项；真实普通 AutoCAD 16项；天正11项；工程副本18项；MCP 摘要／分页4项；原创场景7项；本地标准库5项；学校设计28项、独立CAD11项及交付故障检出6项。工程回归保留源图摘要及141979条既有记录的规范化保留检查，学校样本重建19页交付。

WorkBuddy 5.3.8 随附的 CodeBuddy CLI 2.115.0 已实际发现并调用诊断，完成合成图创建、原子布置／连线／编号、保存后统计及连接验证。使用本次测试的临时配置与许可；保留用户已有全局客户端设置。官方 MCP Inspector 作为第二个独立客户端核验协议与工具调用。具体状态及客户端版本保存在[公开验收摘要](maintenance-summary.json)。

协议故障矩阵覆盖缺失／损坏配置、缺少 PowerShell、未支持 CAD、缺失工作目录、缺失插件、只读发现与无CAD配置的结果恢复。真实故障注入只使用新建合成任务，确认失败DXF不被当作有效交付、已保存DWG可以重开，超时只清理自有进程且后续任务可以运行。

## 分发与限制

开发者预览包增加锁文件中14个 Node 库的1070个文件，保留14份许可文件；本项目插件与脱敏构建记录一起分发。后续用户包还携带官方便携 Node/PowerShell ZIP，缺失运行时可在用户目录准备，不调用系统安装器。现有运行时与锁定依赖可复用，无需 npm 下载或重新编译。[普通用户发行验收](windows-user-release.md)单独记录依赖修复、非提权安装、升级和恢复的结果，以及干净 Windows 的未完成边界。

后续[WorkBuddy 接入验收](workbuddy.md)补充了实际用户目录的 MCP 与 Skill 安装、更新备份、独立引用及已安装配置的7项真实 CAD 验证；随附 CLI 还在项目作用域完成6项绘图证据检查。离线测试增至52项。2026-10-19 完成用户辅助的桌面完整流程：首次信任后加载15工具，全局Skill执行原任务，一次批量绘制后保存重开，独立DXF检查及文件卡片交付；包含7项证据核查和2项用户观察。用户确认卡片可见、手动可以打开；内嵌CAD预览和点击卡片直接调起CAD未验证。桌面控制组件仍不稳定，首次信任、任务输入与打开观察由用户协助。依赖下载／运行时自动安装分支和不同干净 Windows 环境尚需另行验收；同机独立解压目录测试不能代替干净机器。新的通用软件版本、原生交互命令和当前用户文档直连均未扩大承诺范围。

详细本机证据保留在 artifacts 中，不进入公开源码；公开摘要只含版本、测试数量、测量与插件摘要。静态检查不替代宿主实测，历史报告不代替当前DLL和改动的验收。
