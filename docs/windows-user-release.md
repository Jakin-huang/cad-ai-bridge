# Windows 用户预览包

目标是让普通用户解压、连接客户端、用自然语言操作已有软件。用户包带有固定版本的官方 Node、PowerShell ZIP、锁定 Node 依赖及本项目插件，不需要用户安装开发环境、输入 API Key 或编译插件。AutoCAD 2022 和可选的天正 V8 必须已正常安装授权；本项目不分发商业软件。

## 安装与升级

1. 解压 `cad-ai-bridge-2.0.0-preview.1-windows-x64.zip` 用户包到用户可写目录，保留整个目录。双击 **`开始使用.exe`**，点选图纸文件夹，再点“接入 WorkBuddy”。根目录的 [使用说明.html](../使用说明.html) 提供离线图文步骤。
2. 在 WorkBuddy 的“自定义连接器”中核对 `cad-ai-bridge` 启动路径，完成客户端要求的首次信任，等待工具加载；用自然语言让 AI 检查连接并操作图纸。
3. 更新时保留旧目录，在新目录运行同一接入入口。程序从旧连接器读取桥梁配置，沿用原图纸目录、CAD 选择和语言；其他服务不被覆盖。

无需管理员或永久修改 PATH。缺少运行时时，优先读取包内 ZIP，校验固定 SHA-256 后在 `%LOCALAPPDATA%\CADBridge\runtimes` 下按版本解压，之后复用。这里采用较短的路径，避免 Windows 自带 PowerShell 5.1 解压 Node/npm 深目录时超过 MAX_PATH。运行时的官方许可证和第三方声明保留在原始 ZIP 和解压目录中。

离线安装表示桥接程序和运行时无需下载，CAD执行保留在本机；自然语言任务仍使用客户端所选模型。WorkBuddy登录、模型服务可用性和限流另行受客户端约束，不因离线包准备成功而算验收通过。

双击 `restore-workbuddy.cmd` 可恢复上一次接入前的连接器条目与完整 Skill；先结束当前 CAD 任务并退出 WorkBuddy，再恢复并重新打开客户端。恢复保留其他服务、后续新增的服务和已生成图纸；必须保留旧安装目录，旧连接器才能继续启动。新接入被撤销后，首次安装前不存在的本项目条目与 Skill 会被移除。

安装和恢复使用持久化事务记录与互斥锁。进程意外退出后，再次安装会先恢复未完成事务，再安装新版。手动编辑了本项目的配置或 Skill 时，恢复会报告冲突并保留编辑内容。客户端信任与凭据仍由客户端管理，程序不会复制、修改或绕过信任记录。

## 缺失依赖与错误恢复

中文窗口区分“本机准备完成”和“WorkBuddy 已连接”，前者之后仍须在客户端完成首次信任。失败时先显示中文处理建议，“查看日志”才打开技术详情；不要根据旧的成功提示判断当前连接。窗口重新打开时会核对配置摘要，配置被手改后不会沿用旧成功状态。安装过程保持窗口响应，进行中不应重复启动或强制结束。

| 情况 | 行为与恢复 |
| --- | --- |
| Node/PowerShell 缺失 | 用户包从随包 ZIP 准备；开发者包从官方地址下载固定版本并校验 |
| ZIP 损坏或摘要不符 | 损坏缓存改名保留，不执行；重新获取完整用户包后重试 |
| 运行时下载失败 | 最多两次有超时的尝试，删除未完成下载；可改用离线用户包 |
| Node 库缺失 | 在线时运行随 Node 携带的 npm，按锁文件恢复；失败时不改客户端配置 |
| 明确离线且库缺失 | 提示重新解压完整用户包；不尝试网络安装 |
| 目录只读 | 在下载和修改客户端前停止，提示解压到可写用户目录，无需提权 |
| AutoCAD 缺失/不支持 | 明确报告当前仅支持本机 AutoCAD 2022，不创建客户端接入配置 |
| 升级中断 | 重试会先恢复未完成事务；已有本项目配置/Skill被手改时报告冲突 |
| 回退 | 仅恢复本项目条目及Skill；保留其他服务、客户端代理、信任记录和图纸 |

需要强制离线时，可在终端设置 `CADBRIDGE_OFFLINE=1`；普通用户无需设置它。`CADBRIDGE_RUNTIME_HOME` 可覆盖运行时目录，`CADBRIDGE_RUNTIME_CACHE` 可指定官方ZIP缓存。测试使用 `CADBRIDGE_RUNTIME_ISOLATED=1` 排除全局运行时；这些选项不需要进入普通用户操作流程。

## 验收与未完成边界

用户包验收限定本机Windows 10 x64的实际未提权进程；采用独立客户端目录、中文空格及深解压目录、最小 PATH 和离线模式。v2.0使用24工具，版本与实际检查结果见[发行验证摘要](windows-user-validation.json)，未更新到本版的历史报告不作为本版验收。检查覆盖旧版本接入、升级、诊断、真实CAD批量写入和保存重开、原生天正宿主与清理、重装及回退；依赖修复、网络失败、ZIP损坏、解压路径逃逸、升级中断与冲突保护分别记录。开发与CAD专项另见[实用增强验收](practical-validation.json)。

这不等于新装 Windows 或独立标准账户验收。后续已找到 WSL/QEMU 软件仿真路径，下载微软官方评估镜像并启动了隔离虚拟机，但 Windows 安装启动持续停滞，尚未执行来宾内的桥梁测试。按用户要求暂缓本地虚拟机验收，停止测试实例并保留记录；后续优先采用独立实体机或外部 Windows 测试环境。因此发行仍标记 **用户预览**，干净 Windows 与独立标准账户继续为待验收。

下列入口仅作为维护者已有隔离环境的可选工具保存；本轮不推荐或启动本地虚拟机：

```powershell
node scripts/prepare-clean-windows.mjs <已解压用户包目录> <测试报告目录>
```

它生成禁用网络和剪贴板的 `.wsb`，只读映射发行包，仅将指定报告目录映射为可写；不自行启动或改系统设置。在已有 Windows Sandbox 的主机打开该文件即可测试离线运行时、锁定库、CLI 和缺少CAD的正常失败边界。脚本也可在新装虚拟机中运行 `tests/clean-windows.ps1`。新系统未装授权CAD时，这些测试不代表完整CAD或WorkBuddy验收；标准账户及授权软件的完整验收仍需各自实机报告。
