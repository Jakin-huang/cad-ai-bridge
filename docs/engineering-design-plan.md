# CAD AI Bridge 工程设计实施方案

文档整理日期：2026-10-28。能力与验收结果以现有记录为准，本次精简不新增验收结论。

## 定位与目标

把客户需求、建筑条件和标准依据可靠地转为完整、协调、可编辑、可审核的工程成果，并在需求或条件变化后保持一致性。

通用底座管理来源、需求、版本、任务依赖、执行与审核；专业包负责计算、求解和图纸；案例提供输入与独立对照。医院、学校和办公均用于验证复用性，不能将单个案例的名称、答案或例外写入公共流程。

| 已有能力 | 尚未完成的实用性门槛 |
| --- | --- |

## 下一步优先级

| 优先级 | 工作 | 验收重点 |
| --- | --- | --- |
| P0 | 可靠解释独立多文档需求：范围、项目文字、数值、条件、遗漏与冲突 | 冻结原文与评判标准；不预填解释结果；关键需求有来源，未解决项不被隐藏 |
| P0 | 完成支持范围内的公共求解与项目协调 | 建筑/空间条件、标准适用、跨图和变更传播一致；保持原阈值、假设等级与专业待审项 |
| P0 | 验证真实 Agent 的完整交付与恢复 | 同一输入/预算下记录首稿、拒绝、重试与最终成果；最终状态和整轮可用性分别计分 |
| P1 | 扩大受支持布局与安装设计，降低交互及人工返工成本 | 不降低已有质量；用实质不同任务及独立输入验证复用 |
| P2 | 扩展更多专业或 CAD 宿主 | 现有迁移门槛通过后，再以各自真实环境和质量标准验收 |

每轮只解决明确阻断，完成修复、回归、真实验证及文档后收敛提交。不得反复增加同一已知案例的变体，替代项目级能力提升。

## 四个里程碑

| 里程碑 | 目标 | 退出标准与当前状态 |
| --- | --- | --- |
| M1 可追溯设计闭环 | 从有来源的输入到模型、CAD、自检和待审交付 | 声明子集已有证据；输入/对照隔离、CAD重开一致，模拟审核与真实审核分开 |
| M2 完整专项与迁移底座 | 完成普通照明整层专项，并支持医院、学校、办公条件迁移 | 独立建筑空间覆盖100%，用途/目标有来源，真实光度及独立计算/质量核对；至少3个未见条件变体及任务切换隔离。**未完成** |
| M3 实质不同任务协作 | 照明与空间方案共享资料、空间身份、用途变更和协调关系 | 两类设计任务均走通输入、设计、自检、交付和待审；需求/空间/跨图关系100%可追溯，故障注入及A→B→A切换通过，原能力不退化。**未完成** |
| M4 项目级独立验收 | 在声明支持范围内形成高完成度的复杂工程待审成果 | 至少3个未参与开发的真实项目，由独立人员冻结输入/对照，覆盖3类项目、2类实质不同设计任务；关键需求100%有来源且覆盖，一般需求覆盖≥95%，未覆盖显式登记；无缺图/断链，专业重大问题为0、一般意见闭环；新机器及外部用户完成全流程，时间/返工符合预先冻结预算。**未完成** |

## 每次交付的共同要求

1. 冻结原始资料并区分需求、建筑条件、标准、产品假设和最终对照；对照不得参与设计生成。
2. 需求、模型、计算和图纸保持来源与版本对应；来源或设计换版后，旧成果和审核不得继续冒充当前版本。
3. 模型独立自检，CAD保存后独立重开核对；逐张检查输出并交付可编辑DWG、图纸、清单/计算、依据及待审问题。
4. 缺资料、冲突、不适用、失败与未知分别报告；保存失败版本和原始证据，不放宽条件换取通过。
5. 开发完成、本机自动验证、整轮Agent可用性、独立项目和专业审核分别验收；未经人工审核保持待审。
