# 浅进深房间的横向工位布局

本增量扩大实际可生成的布局范围。此前工位只按沿进深排列的桌组求解，宽而浅的房间可能面积足够，却因进深放不下所需排数而失败。新增可显式启用的靠房间后侧横向单排工位；房门仍面向走廊，原桌椅尺寸、席位净空、桌间距、门前连通通道以及原面积、窗接触、路径和相邻关系继续生效。不按医院、学校或办公名称触发。

## 使用与边界

`office-space-planning` 的 `design` 或 `next_step.designBudget` 支持可选 `furnitureMode=allow_transverse_workstations`。未设置或设为 `original` 保持原候选和几何身份；选项不改变工程输入、来源等级或要求。新族可与原布局族、靠边单侧/两侧直走廊、有界改进及来源定义的方案选择一起使用。

这是单排横向工位布局，不是任意家具旋转或任意建筑布局。只有原文允许的设计自由度才可使用；未表达的固定朝向要求保持待解。会议和未配家具空间保持原布局，固定物品及其包络不随工位旋转。人体工学、采光、消防、无障碍、实际施工和专业批准仍需依据与审核。

求解器分别保留同几何下的不同家具候选，避免把两种摆法错误合并。独立审计按实际世界几何复核桌椅与座位区的旋转尺寸、数量、边界、门口、连通通道和关系，不凭布局名称判定通过。新布局的图面编号另做避让，不能占用门前区域、桌椅或座位净空；标注搜索不移动物理对象。旧布局及旧图面分支保持原语义。

## 验证范围

开发声明的28000×5200毫米净壳、固定入口和四段源窗，要求四间工作间、每间四套原尺寸桌椅，总计16席。每间净面积19—22m²，偏好19.72m²，开间至少6000毫米、进深至少2800毫米；还保留窗接触、入口路径及首两间共墙要求。原家具族没有候选，新族完成四间16席，不减少席位、不缩小桌椅，也不提高允许未分配面积。四种入口方向、尺寸/净空不足仍失败、原模式身份及改进搜索的不同家具候选均有回归。

真实客户端从自然语言原文及无program/relations的独立物理基线开始，自行审范围、引文解释房间程序与关系、声明图面文字、覆盖源段并采纳，再求解、自检、CAD保存重开、审核PDF、发布共享空间和项目待审包。控制脚本未提供其scope、草稿或最终房间布置。原文和内部预期均由开发者编写，属于已知合成原文试验，不能称为独立作者、真实客户、盲测或通用语义验收。

首轮实际完成四间16席、69项几何检查和5页图纸，但有两次工具错误：图面说明由短引文拼接支持被正确拒绝，及发布共享空间前读取发布数据失败；客户端自行纠正。首轮严格PDF及原文文字保留通过，逐页查看发现SP03编号靠近门扇线，因此视觉验收不通过。原试轮、错误、五页原图及初版审计全部保留。

首版审计器还错误拒绝了合法`inspect_baseline`，并把开发者内部关系ID当作原文要求；修正后另存最终审计，原审计未覆盖。原文明确的房间ID、全部工程数值、关系端点/类型/下限和状态仍逐项核对；未在原文规定的内部关系ID不作为语义失败。整轮两次真实错误仍不通过，不因审计器修正升级为零错误。

标注修正后的试轮使用逐字节相同的自然语言原文、物理基线和独立预期，另建试轮保存；没有改写首轮任务或放宽原要求。最终统计、源代码快照与专业待审边界见[验收记录](planning-transverse-validation.json)。图面文字一致、声明几何覆盖和可打开CAD均不等于完整工程设计或专业批准。

## 本增量的退出标准

- 原家具模式、两个设计包及来源/版本/交付保护回归通过；新增布局不能以缩小对象或净空换取通过。
- 东西南北入口下的物理尺寸、门前通道、座位区及标注避让成立；同几何的不同家具方案不被误剪枝。
- 实际客户端从原文形成完整四间程序，冻结物理条件及原假设保持，旧布局失败与新布局成功分别有证据。
- 实际CAD保存重开、审核PDF严格解析/尺寸/像素保留、原文标题/范围/全部说明以及逐页可读性分别核对；失败版保留。
- 共享包/项目待审包明确已委托范围、所有待审和专业未批准；开发完成、本机试验、独立实用性验收分别记录。

本轮不增加医院专属规则，不处理医院对照图，不改冻结v2.0或重打发行包。M2—M4及总体目标保持未完成；下一步仍需独立多文档委托、当前条件与标准适用性、更多布局/专业协调，以及真实用户、新机器和专业审核证据。
