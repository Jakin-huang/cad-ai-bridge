# 实际 Agent：条件未知、来源分歧与协调后出图

2026-10-26 用户明确授权本轮合成任务书、合成物理基线、导入标准摘要及公开 IES 计算结果使用当前已登录 Codex 的模型服务。此前的授权阻塞记录保留为历史，不再作为本轮待办。

本轮只验证已有通用闭环：读原文、解释事实与要求、完整登记源段、判断标准条件、按新来源重新准备、设计、真实 CAD 出图和人工审核包。项目名称不参与任务选择，事实/分歧契约共用于照明及空间规划；实际标准类别与这轮 CAD 验证限普通照明。没有扩展为完整建筑、多专业设计或医院专用流程。

两组已知合成用例使用独立物理基线，初始用途未知且无逻辑要求、布灯或最终模型。控制器提供原文和物理条件，Agent 自行解释 scope、十项要求、用途/候选类别及图面标题、范围和说明。第二阶段由控制器明确修订原文，Agent 必须创建新 scope，使用 reprepare 延续原物理基线及假设，再重新解释全部要求。此过程有明确操作指令，不是无提示、独立作者或真实客户验收。

第一组原文尚未确认建筑功能，条件必须 unknown 且不设计。原文补充后条件才可 active。第二组另有医疗、非医疗两条相反陈述；无协调时必须保留分歧、汇总 unresolved/null，协调明确取舍后仍保存被排除陈述及原句，把所选陈述、排除陈述及处置依据带到来源索引和图面。

实际安装的 Codex CLI 保留当前登录及模型配置，无模型/服务覆盖、无凭据值读取。工程试验仅配置四个 CAD Bridge MCP 工具，关闭命令、补丁、联网及多 Agent 功能；最后的定向能力查询只开放一个只读 intake 工具。修正测试入口的 `--ignore-user-config`：旧选项会跳过用户模型配置，本轮已移除。运行后的源码快照与最终产品运行代码另行核对，测试脚本和文档的后续变化单独记录。

原项目数值保持平均照度 80–200lx、均匀度至少 0.40、功率密度最多 8W/m²；候选类别依据当前来源激活后，取较严交集 100lx、0.60、4W/m²。不得改原值、降低标准或更换类别来通过测试。专业适用性、现场权威及全部规范覆盖始终待审。

独立审计重新编译实际采纳草稿，核对不可变输入、全部要求、源段覆盖、事实/条件、历史失效与准备链；重新校验来源绑定、设计、模型与保存后重开 DWG 的属性/字节、操作次数和每张 PDF。PDF 严格解析、原件/审核件像素一致、原文标题/范围/全部说明可提取，并逐张查看。完整源段登记只代表结构覆盖，不能替代语义完整性。

第一份独立审计误把 Agent 对自己当前子任务的只读状态查询判为越界。该失败报告原样保留，审计只补允许对已绑定本任务的只读 status，没有放开直接准备、设计或控制器修补。其他历史失败版本、旧任务、输入、模型、原图和 PDF 均保留；新证据使用新文件名。

分歧用例首次实际执行有一次草稿拒绝：Agent 将多行原文复制为 notes[2].text；自行纠正后最终工程状态通过，但整轮零错误门槛失败。原状态、输入和六张审核页完整保留。原单段限制使用服务端 refine，JSON Schema 未完整公开该规则；改用等价 pattern，让两种设计任务的 capabilities 都能展示。Skill 说明 text 必须是原文连续单段、quote 可以跨行，不能删换行拼接原文。没有放宽输入规则，也没有自动修补 Agent 草稿。使用相同原文/物理条件另起实际客户端复验；第一组、保留失败组及修正组逐一列入验收记录，不用最终出图掩盖失败轮。

修正组在来源明确后的设计/出图阶段47次调用无错误，五个原图类加一张说明续页通过检查；但未知阶段结束前额外查询 capabilities/summary 时仍有一次拒绝，因此该整轮也保留为失败。补充通用只读概览，返回任务类型、边界和可查询入口，不改变默认参数契约或准备/设计门槛。原失败请求在只读模式精确重放通过，最终代码的实际客户端分别查询两种任务，共两次调用无错误，174个原数据文件字节不变、零新增数据文件和CAD操作。

本轮到此收敛：三份最终DWG、17张PDF均完成独立核对/逐页查看，两个整轮失败原样保留。未在最后的只读入口修改后再跑一整轮CAD，所以不声称最终源码整轮零错误验收通过。最终代码已重新核对三组原工程证据；早期客户端运行时与最终源码的差异、最后定向客户端的完整运行时代码匹配分别记录。这些区别不能由定向重放或单元测试替代。
