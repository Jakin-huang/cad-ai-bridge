# 物理空间、来源别名与兼用功能

一个物理空间可能同时有主名称、别名或兼用功能标签。不能将每个标签都计作独立房间，也不能为消除重叠而删除原始名称。当前功能提供可追溯的显式解释，不自动确认建筑身份或判断用途相同。

`inspect_architecture.expectedRooms` 的每项表示一个声明的物理空间。可附 `aliases`，每项须给出独立ID、原始名称、单个实例路径或有序文字片段路径、`relationship` 和解释理由。关系只能是 `alternate_name` 或 `secondary_use`；所有物理空间与附加标签ID必须唯一。文字拼接仍按[来源文字](architectural-text.md)的规则核对，片段不得重复用于其他空间/标签，也不得同时被排除。

主标签确定边界，附加标签必须严格位于同一边界内部，且不能对应另一个或多个明确闭合区域。位于边界上、外部、其他明确区域或重复引用均阻断。明确闭合边界得到 `same_observed_boundary`；推断空间中只记录 `inside_inferred_boundary`，不能因此成为已签发建筑。空间包含关系不证明名称关系或功能适用性，标签始终标记 `unverified_interpretation`。

`coverage.expectedRooms` 是声明物理空间数量；`expectedLabelEntries`、`matchedLabelEntries` 统计主名和附加名称。`space-labels.csv` 保留所有已匹配名称与原始路径。旧请求、旧清单和旧源图保留，重新解释需要新请求。自动邻接建议不会进行空间合并。

项目种子通过已绑定摘要的建筑包接收 `room.sourceSpaceLabels`，包含来源ID、名称、原始路径、关系与待审解释。种子预填了与建筑包冲突的标签时拒绝，不静默覆盖。普通别名作为待审解释；缺少明确评估的 `secondary_use` 仍触发 `SECONDARY_SPACE_USE_UNSUPPORTED`，即使几何完整或填写了主用途也不能设计。新增[共同用途方法](shared-use-lighting.md)仅允许来源、标准类别和共同条件完整的普通用途进入严格交集复核。直接 `prepare` 同样执行检查，不能靠绕过建筑导入入口遗漏兼用功能。

设计模型记录附加标签的建筑证据摘要。摘要对JSON属性顺序不敏感，但保留有序文字片段的意义。独立检查器核对模型输入的标签摘要，检出附加名称被删改；兼用功能不能只修改成单一用途后通过。CAD设计说明按物理空间/标签ID写入原名、来源和待审状态，独立场景检查及保存重开核对说明文字；物理数量、面积和回路只按物理空间计算一次。交付前重新核对原建筑包和捕获摘要，发生变化时在原生新建之前阻断。

任务中心新增经登记摘要读取的结构化标签视图，使用文本节点展示物理空间、附加来源名、声明关系、空间核对和可展开来源解释，同时保留建筑注记。该视图已实际浏览器核对；标签CSV下载与登记摘要一致。它不执行来源HTML。独立 `spatial-review.html` 仍没有完成浏览器布局/交互目视验收，与任务中心的已验证视图分别记录。

本机验证包括独立程序生成建筑源图至项目输入、单物理空间设计、真实CAD保存重开、五张A3输出和逐页目视检查。产品为明确假定参数，计算采用利用系数估算；本用例验证来源标签贯通与数量一致性，不是光度质量、医院设计或新客户验收。兼用功能及来源变更负例均未进入新建图纸。

医院同一历史建筑根块另外重新读取。两个电梯的括号说明作为显式、未确认的兼用解释，原43条来源名称保留为41项声明物理空间加2个附加名称；这不是独立建筑确认的41房间清单，也不是已修正原图。37项为推断几何，仍有4个未解析和1组独立重叠；两个兼用关系、入口/吊顶、独立空间表、原客户要求及专业适用性均待确认。原43项清单及其3组重叠记录保留，不能以分母变化宣布空间覆盖率提高。

下一步重点是有明确来源时的多用途标准适用性与约束交集、建筑条件变更影响、非矩形边界和开口来源、整层计算预算。不能以附加标签或单房间测试完成替代项目退出标准。最新[验证记录](physical-space-labels-validation.json)区分自动检查、本机流程、浏览器/图面检查及外部验收；M2—M4保持未完成。
