# 从业务需求生成学校电气项目

`cadbridge school` 从结构化需求生成原创教学楼协调底图、设备及接线，输出可编辑 DWG、DXF、14 张 A2 矢量 PDF、设备/回路/数量 CSV、计算报告和验证证据。它演示完整的数据到出图闭环，设计阶段是**方案深化与自动出图验证**，审查状态始终为“待专业审定”。当前没有建设地点、正式建筑底图、供电接口或真实灯具配光文件，不能将示范直接作为施工图。

## 项目需求

[需求文件](../examples/school-requirements.json)定义启明小学二层教学单体，每层三间普通教室、每班30人，共180人。单层42m×11.6m，总建筑面积974.4m²。每层设置两端楼梯、3.6m走廊、卫生间、强弱电间。建筑是自行绘制的协调底图；墙体、结构、防火、疏散、门窗、无障碍和其他专业由实际项目重新确认。

供电假定为校园380/220V TN-S，普通电源与消防电源分开；消防报警、集中应急、广播及网络接已有校园系统。无宿舍、实验室、食堂、电梯及电空调，采暖通风由校园另行保证。没有把未知的空调和消防泵负荷默认为零后宣称完成整座校园设计。

## 一条命令运行

先完成 `cadbridge setup` 以及 AutoCAD/天正的正常安装授权。学校出图另需 Python、`reportlab`、`pypdf` 和本机黑体字体；可用 `CADBRIDGE_PYTHON` 指定 Python。PDF 为同一已核验模型的矢量输出，并非 AutoCAD 打印。

```powershell
python -m pip install reportlab pypdf
node bin/cadbridge.mjs school examples/school-requirements.json
```

该命令先检查渲染依赖、需求和业务约束，再启动 CAD。每次生成独立目录 `artifacts/school-projects/school-*`，不会覆盖已有交付。最后的目录指针在 `artifacts/school-project-current.txt`。运行 `node bin/cadbridge.mjs school --model-only` 可先离线检查和保存模型，不启动 CAD，也不需要Python。

参数允许1～3层、每层1～4间教室及有限的尺寸调整。它是明确边界的教学楼模板；不是任意校园的自动建筑设计器。输入导致容量、照度或压降不满足条件时会停止，不在失败模型上继续出图。

## 技术方案与实施流程

1. **需求和依据**：严格校验 JSON，记录日期、范围、学校人数、建筑尺寸、产品目标与工程假设。标准版本单独登记，采用的事实与待审项分开。GB17945-2024已替代本地2010版；GB7793-2025将在2026-11-01实施，本次不冒充已经完成新版全部审查。
2. **统一业务模型**：房间、设备、稳定ID、设备号、所属回路、配电箱、相别、负荷、系统类别及图页保存到 `design-model.json`。只在唯一设备视图计数；总图图例与系统框图是静态图形，不进入设备数量。
3. **计算与预检**：利用系数法估算桌面/黑板平均照度，核对自定功率预算；普通回路按装机计算Ib，馈线按需用系数分相汇总；在显式载流量假设下检查Ib≤In≤Iz和累计简化压降；检查应急容量、36V支路电阻压降初估、信息铜缆长度、回路归属及可达性。
4. **确定性场景**：仅允许图层、普通图块、折线、圆、单行文字与有限属性。`cad_create_drawing` 在新空白图中一次事务建立底图、图框、说明和原创符号，不执行任意LISP、命令或外部引用。
5. **设备布置、接线、编号**：复用 `electrical_apply`，按图块分批布置，按明确路径接线，再实际执行编号操作。每批使用UUID、DWG摘要和文档版本；每次另存新文件并校验输入文件未变。
6. **CAD闭环验证**：独立AutoCAD进程重新打开最终DWG，检查全部设备属性、坐标、端点与长度；独立DXF解析器逐一核对所有静态实体、文字和原创图块几何，再在天正宿主打开。新图使用普通AutoCAD对象及本中间层元数据，不声称具有天正原生关联拓扑。
7. **交付与复核**：生成PDF、业务报告、CSV、文件摘要清单。验证PDF页数、标题与纸面边界；最终发布前渲染检查各页。真实项目的专业复核事项保留在报告及模型内。

## 图纸及交付

基准项目14页：总说明与目录图例；两层照明；两层插座及小动力；两层应急疏散；两层消防报警/信息/广播；低压配电单线系统；出线回路表；弱电及应急系统；屋面防雷预留；基础接地。模型包含292个设备及接口、278条显式接线、42个回路。图框均在DWG模型空间中按毫米1:1组织，各A2图框对应1:100打印比例；系统图注明示意。打开DWG默认定位首页；命名视图E-01至E-14对应每张图，在AutoCAD中用 `-VIEW` → `Restore` → `E-02` 等切换。

普通装机10.296kW，需用7.416kW。每教室12盏24W/3600lm一般灯、3盏16W黑板灯，利用系数法约327lx与622lx，灯具输入功率密度约4.895W/m²。每层应急末端120W，电源150W，90min设计所需电池铭牌容量至少约257.143Wh（按可用系数0.7）。这些结果依赖需求中的显式假设。

PDF和HTML报告由模型生成，只有CAD逐项核验通过后才允许渲染。`manifest.json`保存交付文件摘要，`delivery.json`记录最终DWG、宿主任务、验证数量和待审事项。CSV同时保存图面长度、估算敷设长度和电气计算字段，不将图面长度当成采购量。应急电源AC输入、消防电源干线、光纤/广播干线及厂家闭环拓扑仍在明确的校园接口深化范围内。

42个模型回路/链路分组由18个普通电源支路、8个应急直流支路、12个信息星形链路、2个楼层火警段和2个广播分区组成，不能解释为42条交流馈线。两个火警段最终如何接入同一校园闭环及隔离分段，须按厂家设计确认。

## 必须保留的工程边界

没有真实IES/LDT时，不输出伪造的逐点最低照度、均匀度或UGR“通过”；没有短路及接地资料时，不输出Icn/Icu、选择性、0.4s切断、接地电阻或防雷分类“通过”。载流量为假定修正值，保护与线缆仍需按真实产品和敷设条件复核。报警布点、隔离分段、消防闭环、联动矩阵、应急续航、产品认证、地方标准及建筑专业审定均列为待完成事项。

## 持续维护

公共仓库只保存原创需求、符号生成逻辑、标准登记摘要和可复现测试；不包含本地医院DWG、规范全文、商业天正模块或本机路径。CAD和PDF生成结果默认忽略。修改需求重新运行，保留旧目录方便比较，禁止手改CSV使其脱离CAD模型。

需要分享完整原创示例时运行 `node scripts/package-school-example.mjs`，另生成图册/图纸/模型/表格ZIP与SHA-256。脚本核对每个文件摘要，剔除任务日志与JSON中的本机路径，把交付链接改成相对路径；不包含商业插件或医院图纸。公开DXF副本仅清除空白CAD模板带入的旧打印机绝对路径，记录前后摘要并再次校核几何；原生DWG保持不变，未做二进制元数据改写。源码预览ZIP和示例交付ZIP分别保存于dist，均不自动上传。

离线单测覆盖完整模型、改变层数/教室数、容量不足、照度不足、回路断点、缺失归属和声明式场景越界。`tests/school-delivery.mjs` 在内存副本中故意破坏设备号、静态文字、路线图层、路线顶点及命名视图，验证独立回读能检出错误，不修改交付文件。宿主回归保留原有实际工程图副本用例、事务回滚、UUID重放、原图保护及MCP分页检查。只有当前DLL对应的回归通过后才能打包本地预览发行，不自动推送。
