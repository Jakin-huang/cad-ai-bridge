# 物品变更审核与固定条件冲突

这是未打包的源码增量，继续使用共享规划、来源审阅、同任务修订和通用操作收据，不按医院、学校或办公名称选择逻辑。

新生成的修订模型在存在物品变更历史时使用图面第8版，增加 SP07 及必要续页，呈现物品旧新值、保留处置、理由、来源文档及摘要。完整引用、来源版本和旧新输入身份另写入绑定的 asset-changes JSON/CSV，包含在交付及待审文件中。旧模型按原版本重建，不补写或追认为新审核页；报告最多承载200项历史变更，超出明确阻断，不能静默漏报。

固定物品的本体及声明操作净空必须包含在给定壳内。公共输入预检直接给出 FIXED_ASSET_OUTSIDE_SHELL、物品ID、固定值、所需包络和壳范围；该条件不能通过自动移动、缩小或删设备放行。它证明的是声明条件之间的几何冲突，不认证现场尺寸、设备参数或项目权限，也不等同于完整求解所有矛盾。

本轮真实 Agent 暴露了另一项问题：原始任务的“尺寸逐项保留”曾被采纳为项目说明，后续尺寸修订仍沿用这句话。原句存在且投影一致，不能证明它对当前条件仍然成立。失败 R1 保留，不能算最终状态通过。

对此，新 revise_assets 对已有 drawingPresentation 的任务要求显式 presentation 审阅，结构仍为 title/scope/notes、完整 spaceIds、reason/evidence 及 reviewed=true。名称、描述性范围和空间列表保持；说明重新按当前原文判断适用性，过时指令作为历史背景。新原文引文仍须字面有效，最终字段与原文覆盖仍需完整审阅和绑定。旧记录没有这个参数时仍按原历史规则重建，不能因新门槛而改写旧失败。该机制要求 Agent 作出并记录判断，**不是自动证明任意说明语义一致**。

实际接续为同一正式任务 R0→R1→R2→R3：R0 为首版；R1 两项尺寸变更和 SP07 生成，但过时说明未清除；根据控制端审核反馈，Agent 沿现有同源文字修订流程在 R2 修正说明，工程值不变，再生成可审阅图。R2 当前状态校核通过，但客户端两次误把读取响应包装当作入参，自行纠正后完成，因此全过程零错误门槛失败。控制端没有代写替换说明，但提供了具体的语义问题反馈，不能称作未经反馈的独立理解验收。

之后 R3 的新协调原文明确改变固定柜宽度，保留原坐标和其他条件。Agent 完成新输入、项目说明和来源审阅后，根据预检停止，没有调用设计、CAD交付或发布共享空间；旧模型、图纸、PDF和已发布共享包保持历史字节，旧共享来源不再 current。R3 是预期阻断验收通过，**没有新设计验收通过**；R2 七页是上一可审阅历史版本，不能当成满足 R3 条件的交付。

以上为当轮封存时的R3状态，原失败及验证边界见[验证记录](asset-review-and-conflict-validation.json)。后续[同任务来源恢复](asset-recovery.md)已将该测试接续到R4，不追认R3曾产生可用设计。陌生委托的语义完整性、下游照明等专业的实际消费/重算、外部用户、新机器和专业审核仍未验收。冻结 v2.0、既有预览包和标签保持；完整复杂工程目标及 M2—M4不标完成。
